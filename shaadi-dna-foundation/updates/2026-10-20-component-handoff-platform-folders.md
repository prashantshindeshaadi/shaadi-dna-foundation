# Component handoff: one folder per component, platform subfolders

**2026-10-20**

## What changed

- **Component handoff rule** added to `skills/shaadi-code-connect/SKILL.md`. Each component's folder is the single place for everything about it:
  - `<sh-name>.md` is the blueprint. Its purpose, switches, rules and taps come from the Figma component and variant descriptions; properties, anatomy and tokens are generated by `tools/components.py`.
  - `web/` holds HTML and CSS plus the Code Connect file (`html` parser).
  - `compose/` holds Jetpack Compose plus `*.figma.kt`.
  - `swiftui/` holds SwiftUI plus `*.figma.swift`.
- Platforms are Web (HTML/CSS), Jetpack Compose and SwiftUI only. No XML views and no UIKit.
- One Code Connect config per platform, each scoped to its own subfolders. Dev Mode keeps the Markdown blueprint link and adds Web, Compose and SwiftUI labels.
- `components/README.md` and its generator now describe the platform subfolders.
- FPV components in Figma now carry their logic in their descriptions (`Purpose`, `Built from`, `Switches`, `Rules`, `Taps`, and `When:` per variant), ready to flow into their blueprints.

## Why

Logic, data and code for a component should live together and come from one source (Figma), so web, Android and iOS build the same behaviour.

## Who needs to do something

- **Designers:** write behaviour in the Figma description (component and variant) before handoff.
- **Developers:** put platform code in the component's `web/`, `compose/` or `swiftui/` folder; use the token code-syntax names.
